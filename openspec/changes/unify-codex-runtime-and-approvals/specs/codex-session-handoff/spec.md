# Spec Delta

## Purpose

定义 Codex 在聊天和终端之间继续同一会话时的身份与交接契约，让用户看到最新历史并避免 agentui 管理的多个进程同时写入同一会话而产生分叉。

## ADDED Requirements

### Requirement: 交接保持原会话身份
系统 SHALL 使用明确的原 Codex thread ID、项目路径和一致的运行配置完成交接；恢复失败 SHALL 显示错误并保留原选择，不得自动新建或恢复全局最近会话。

#### Scenario: 聊天切到终端
- **WHEN** 聊天回合已完成，用户将已有会话交接给终端
- **THEN** 新终端恢复该 thread 并加载最新历史，不打开无关会话

#### Scenario: 恢复失败
- **WHEN** 原会话不存在、格式不兼容或 CLI 恢复退出失败
- **THEN** 页面报告恢复失败，新建会话仅由用户另行明确发起

### Requirement: 管理内会话独占写入
系统 SHALL 对 agentui 管理的同一 Codex 配置空间与 thread 保持至多一个写入端。浏览历史不要求转移写入权；活动运行或待审批时 SHALL 提示用户先等待或中止，不静默强制交接。

#### Scenario: 活动聊天时打开终端
- **WHEN** 聊天正在生成或等待审批，用户打开该会话终端
- **THEN** 系统展示等待或中止后交接选项，不启动可写的第二个运行

#### Scenario: 终端存活时发送聊天
- **WHEN** 终端持有该会话写入权，用户在聊天发送消息
- **THEN** 系统要求交接；仅在终端退出且资源回收确认后启动聊天回合，不丢弃待发送消息

#### Scenario: 并发交接请求
- **WHEN** 两个浏览器连接同时申请同一会话的写入权
- **THEN** 仅一个成功，另一个收到占用状态，不发生重复启动

### Requirement: 交接刷新历史并隔离缓存
系统 SHALL 在终端释放后刷新聊天历史，在聊天修改后重新启动终端恢复最新内容；缓存 SHALL 按用户、provider、项目和会话隔离，不复用属于其他入口或配置的进程。

#### Scenario: 终端完成后回到聊天
- **WHEN** 终端写入新消息并完成交接
- **THEN** 聊天在允许下一次发送前加载新增历史，不要求手动刷新整页

#### Scenario: 旧终端重连
- **WHEN** 聊天已推进会话或运行配置已变化，用户重新进入终端
- **THEN** 系统不把旧缓冲回放当作最新会话，而是释放旧进程并从明确 ID 恢复

#### Scenario: 断线与服务重启
- **WHEN** 终端连接断开但进程仍存活，或 agentui 服务重新启动
- **THEN** 断线不自动释放仍存活进程的写入权；重启后核验旧运行已清理再允许新运行，避免残留锁或重复写入

### Requirement: 明确交互入口边界
系统 SHALL 告知用户聊天和终端是同一会话的不同交互入口，展示当前运行来源和占用状态；不宣称两者共用同一进程或完整复现官方 App。外部启动的 Codex 不属于管理内互斥保证。

#### Scenario: 查看终端状态
- **WHEN** 用户查看 Codex 终端连接信息
- **THEN** 能看到版本、当前会话及写入端状态，并能区分恢复失败和正常新建
