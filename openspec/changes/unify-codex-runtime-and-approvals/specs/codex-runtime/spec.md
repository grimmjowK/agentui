# Spec Delta

## Purpose

为 agentui 中的 Codex 提供一致且可诊断的运行基础，使聊天、终端、认证和模型查询使用同一运行来源，并可靠地呈现输出、错误、取消和版本不兼容情况。

## ADDED Requirements

### Requirement: 所有 Codex 入口共享运行来源
系统 SHALL 对聊天、Codex 终端、认证和模型查询使用相同的可执行文件解析结果及 Codex 配置根目录，优先显式配置，其次可用的 macOS App 内置程序，最后系统 PATH；显式配置无效时 SHALL 报错而非静默替换。

#### Scenario: 本机安装多个版本
- **WHEN** App、全局 npm 与项目依赖中存在不同 Codex 版本，且未显式指定路径
- **THEN** 所有入口选择同一个符合优先级的程序，不因 SDK 自带二进制而偏离

#### Scenario: 显式配置无效
- **WHEN** 用户指定的路径不存在或无法执行
- **THEN** 所有入口报告该路径错误，不自动选择其他版本

#### Scenario: 路径包含空格
- **WHEN** 所选程序路径含空格或 shell 特殊字符
- **THEN** 系统执行该程序本身，不拆分或执行路径中的字符

### Requirement: 运行能力可诊断
系统 SHALL 展示有效运行来源、版本及聊天审批能力状态；仅允许通过实际协议验证的版本或能力组合进入交互聊天，不兼容时 SHALL 明确失败且不得静默退回无审批运行。

#### Scenario: CLI 不支持必需协议
- **WHEN** 所选程序无法完成初始化或缺少必需的命令/文件审批能力
- **THEN** 聊天入口显示兼容性错误和有效版本，禁止自动改用另一程序或宽松权限

#### Scenario: 切换运行配置
- **WHEN** 用户改变可执行文件配置而已有会话仍存活
- **THEN** 系统提示需要结束旧运行再重连，新的聊天和终端均使用新配置，不在运行中替换程序

### Requirement: 聊天保留会话与流式输出契约
系统 SHALL 保留 Codex thread 身份，展示增量文本、工具状态、错误及可用使用量，避免增量与最终内容重复；认证失败、协议失败、取消和成功 SHALL 具有互斥终态。

#### Scenario: 流式消息完成
- **WHEN** 同一消息先收到多个增量再收到最终内容
- **THEN** 页面显示一份完整消息，历史与实时结果不重复

#### Scenario: 中止或进程退出
- **WHEN** 用户中止运行或底层进程在运行中退出
- **THEN** 系统结束该运行，保留已有内容并清理进程和待处理请求，不再补发成功终态

#### Scenario: 恢复旧聊天
- **WHEN** 用户选择已有 Codex 会话继续发送
- **THEN** 系统使用原 thread ID；无法恢复时显示错误，不伪装成同一会话的新建运行
