# Spec Delta

## Purpose

让用户在 Codex 聊天中看到真实待审批操作，选择明确授权范围后继续原任务，并确保请求在多用户、多会话、断线和取消时不会被错误批准或遗留。

## ADDED Requirements

### Requirement: 真实审批请求展示并暂停操作
当 Codex 请求命令、文件修改或受支持的额外权限时，系统 SHALL 展示操作详情、原因及授权范围，并等待用户决定；审批前 SHALL NOT 执行待批准操作或模拟批准成功。

#### Scenario: 命令与文件审批
- **WHEN** 运行请求执行命令或修改文件的授权
- **THEN** 聊天显示命令和工作目录或文件变更信息，用户能批准或拒绝，运行保持等待

#### Scenario: 额外权限审批
- **WHEN** 运行请求访问网络或额外文件路径，且当前版本支持该能力
- **THEN** 界面展示所请求的主机或路径及作用范围，回复不授予请求之外的权限

### Requirement: 决定返回原请求并尊重策略
系统 SHALL 将用户决定仅返回对应 Codex 请求，批准后继续原回合、拒绝后不执行该操作；默认交互模式 SHALL 允许审批，策略禁止提升权限时 SHALL 显示限制原因，不伪造可解除限制的按钮。

#### Scenario: 批准后继续
- **WHEN** 用户批准仍有效的请求
- **THEN** 原回合继续并展示工具结果，不重发整条用户消息、不创建新 thread

#### Scenario: 拒绝与权限范围
- **WHEN** 用户拒绝请求，或仅批准一次操作
- **THEN** 拒绝的操作不执行，一次授权不变成永久或其他会话授权

#### Scenario: 运行禁止申请权限
- **WHEN** 当前配置禁止审批或宿主限制无法提升
- **THEN** 页面展示限制来自何处及该操作的失败，不默认改为全权限运行

### Requirement: 审批身份与生命周期一致
系统 SHALL 将待审批请求绑定认证用户、provider、thread、turn、请求 ID 和运行实例；只接受有效归属的首次决定，过期、重复及跨用户回复 SHALL NOT 触发操作。

#### Scenario: 伪造或重复回复
- **WHEN** 回复来自其他用户、其他会话、旧运行实例或已完成请求
- **THEN** 后端拒绝或幂等忽略回复，不向当前运行授予权限

#### Scenario: 断线重连
- **WHEN** 同一用户在请求仍有效时重连
- **THEN** 页面恢复待审批卡片；断线期间不自动批准，过期请求显示已失效

#### Scenario: 中止超时或退出
- **WHEN** 用户中止回合、审批超时、运行进程退出或服务关闭
- **THEN** 所有相关卡片结束等待，清理待审批请求；若协议允许则回传取消或拒绝，不继续执行

### Requirement: 审批回复按 provider 路由
系统 SHALL 为 Codex 决定使用独立且可辨识的回复契约，保留其他 provider 原有审批行为。

#### Scenario: 多 provider 同时等待
- **WHEN** Claude 与 Codex 分别存在待审批请求，用户批准 Codex 请求
- **THEN** 仅对应 Codex 运行收到决定，Claude 请求保持不变
