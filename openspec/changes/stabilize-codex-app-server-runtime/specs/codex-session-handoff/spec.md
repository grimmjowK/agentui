# Spec Delta

## Purpose

为服务端非正常退出后残留的会话独占锁提供结构化诊断与有门槛的显式恢复路径，
减少对人工核对并删除磁盘目录的依赖，同时不削弱现有的双重进程身份校验。

## ADDED Requirements

### Requirement: 异常锁可被结构化诊断
当会话独占锁的持有方身份无法通过双重进程身份校验确认已退出时，系统 SHALL 提供一个只读的
诊断操作，展示该锁的持有方类型、声明时间、距今时长，以及双重身份校验针对服务端进程和子进程
分别得出的结论；不得要求用户直接读取或猜测磁盘上的锁文件内容来做判断。

#### Scenario: 查看无法确认存活的锁
- **WHEN** 用户或管理者对一个双重身份校验无法确认已退出的会话锁执行诊断操作
- **THEN** 系统返回该锁的持有方类型、声明时间、距今时长，以及服务端进程和子进程各自的身份
  校验结论（已确认退出、已确认存活、或无法确认）

### Requirement: 异常锁的显式恢复需要门槛与二次校验
当双重身份校验长时间无法确认锁持有方已退出，且超过可配置的存活判定时限时，系统 SHALL 允许
一次显式的强制释放操作；该操作执行前 SHALL 重新核对一次双重身份校验结论，若此时发现持有方
已恢复响应则 SHALL 中止释放并报告冲突，不得在未重新校验的情况下直接释放。

#### Scenario: 超时后显式释放
- **WHEN** 一个锁的双重身份校验结论长时间保持"无法确认"且已超过配置的时限，用户执行显式
  强制释放操作
- **THEN** 系统在释放前重新核对身份，确认仍无法确认持有方存活后才释放锁，释放后记录该操作
  的执行者与原因

#### Scenario: 释放前发现持有方已恢复
- **WHEN** 用户执行显式强制释放操作，但重新核对时发现锁持有方的身份校验已能确认其仍然存活
- **THEN** 系统中止释放操作并报告冲突，不释放仍被合法持有的锁

### Requirement: 自动回收路径保持不变
当双重身份校验明确确认服务端进程和子进程均已退出时，系统 SHALL 继续沿用既有的原子回收流程
（标记恢复中、重新核对锁的世代标识、原子替换后清理），不因新增的诊断与显式恢复路径而改变
明确已退出场景下的自动回收行为。

#### Scenario: 两端身份均明确退出
- **WHEN** 服务端进程和子进程的双重身份校验均明确确认已退出
- **THEN** 系统按既有的原子回收流程自动回收该锁，不需要用户执行显式恢复操作

#### Scenario: 终端 preflight 过渡期不误回收活动租约
- **WHEN** 当前服务端进程仍持有某个会话的内存租约（如终端 preflight 临时探测进程刚退出、即将挂载正式 PTY 进程的过渡窗口）
- **THEN** 系统保持该租约为占用状态，不会因临时子进程退出而误判为孤儿锁回收
