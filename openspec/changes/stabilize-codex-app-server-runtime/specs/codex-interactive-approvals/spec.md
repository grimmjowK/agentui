# Spec Delta

## Purpose

修正审批决定过滤逻辑在新版本协议返回仅含不支持决定类型时可能导致候选列表为空的缺口，
确保任何审批请求都至少有一个安全的候选决定。

## MODIFIED Requirements

### Requirement: 真实审批请求展示并暂停操作
当 Codex 请求命令、文件修改或受支持的额外权限时，系统 SHALL 展示操作详情、原因及授权范围，
并等待用户决定；审批前 SHALL NOT 执行待批准操作或模拟批准成功。当协议提供的候选决定集合经过
受支持范围过滤后为空时，系统 SHALL 回退为仅提供拒绝选项，不得展示没有任何可选项的审批卡片。

#### Scenario: 命令与文件审批
- **WHEN** 运行请求执行命令或修改文件的授权
- **THEN** 聊天显示命令和工作目录或文件变更信息，用户能批准或拒绝，运行保持等待

#### Scenario: 额外权限审批
- **WHEN** 运行请求访问网络或额外文件路径，且当前版本支持该能力
- **THEN** 界面展示所请求的主机或路径及作用范围，回复不授予请求之外的权限

#### Scenario: 候选决定集合被过滤为空
- **WHEN** Codex 协议为某个请求提供的候选决定全部是系统当前不支持展示的类型（例如需要额外
  UI 展示策略修正内容的对象型决定）
- **THEN** 系统为该请求提供仅含拒绝的候选决定，不展示空白或无法操作的审批卡片，并记录一条
  诊断日志说明原始候选决定被过滤的情况

### Requirement: Codex 审批卡片与其他 provider 视觉一致
系统 SHALL 以结构化卡片展示 Codex 审批请求，包含请求标题、操作摘要（命令审批展示命令与工作
目录，文件审批展示涉及的文件或变更摘要）以及可折叠的完整请求详情；SHALL NOT 以未经组织的
原始 JSON 转储作为审批卡片的主体内容。审批卡片的外观 SHALL 与其他 provider 的审批卡片保持
一致的卡片外壳与排版。

#### Scenario: 命令审批卡片
- **WHEN** Codex 请求执行命令的授权
- **THEN** 卡片主体以可读方式展示待执行命令与工作目录（以及存在时的原因），完整请求内容收入
  可折叠区域，不在主体直接展示原始 JSON

#### Scenario: 文件审批卡片
- **WHEN** Codex 请求修改文件的授权
- **THEN** 卡片主体展示涉及的文件或变更摘要，完整请求内容收入可折叠区域

#### Scenario: 未知类型请求兜底
- **WHEN** Codex 请求的类型不属于已知的命令或文件审批
- **THEN** 系统沿用统一的审批卡片外壳展示标题与可折叠详情，不退化为裸 JSON 展示
